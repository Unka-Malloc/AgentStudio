# Storage Port With Local Backends

Pactium defines a storage port so proof algorithms are decoupled from persistence mechanics. The current package ships local JSON and SQLite storage adapters behind the same `StoragePort` contract. The root `createStoragePort()` factory defaults to the JSON backend for compatibility, and `storageBackend: "auto"` runs a SQLite capability detector before choosing SQLite for new data directories when a Pactium-supported provider is available (`node:sqlite` or optional npm `better-sqlite3`), otherwise JSON.

Storage backends store and retrieve protocol material; they do not define canonical encoding, hash roots, proof formats, or verification semantics. SQLite capability detection reports npm, CLI, and platform package-manager signals across operating systems, while backend selection only uses implemented storage-capable providers. Data directory manifests bind the selected backend: existing JSON directories continue to open as JSON, SQLite directories require SQLite support, and Pactium does not silently fall back to a different backend for an already initialized directory. Adding another backend requires implementation, tests, and an ADR update before docs may describe it as current behavior.
